## Category A — unqualified `Some(...)` / `None` instead of `Opt.Some(...)` / `Opt.None`

vāṇी requires enum variant construction to be qualified with the enum type
name (`Opt.Some(v)`, `Opt.None`) — see any working `option_types.vani` (e.g.
`examples/language/persian/option_types.vani`, `examples/language/urdu/option_types.vani`)
for the correct pattern. The following dialects' `option_types.vani`,
`try_question_op.vani`, and (where it constructs an `Option`-typed struct
field) `box_recursive_drop.vani` write bare `Some(...)` / `None` instead,
producing "unknown function 'Some'" / "unknown variable 'None'":

amharic, burmese, cherokee, georgian, japanese, khmer, korean, lao,
mandarin, mongolian, thai, tibetan (tibetan only `option_types.vani` +
`try_question_op.vani`, not `box_recursive_drop.vani`; tibetan also has
a separate `verified.vani` failure, see Category C).

Fix: prefix every bare `Some(` / standalone `None` in these files with the
dialect's own `Opt.` — check each dialect's actual struct/enum-access
operator token first (should be `.` universally, but confirm) and whichever
local translation of the enum type name `Opt` the file already declares
(`enum Opt { Some(i64), None }` — check whether these dialects render `Opt`
itself in translated form; if so, qualify with THAT identifier, not literal
`Opt`).

## Category B — dropped `ref` on repeated Vec-parameter calls (move-after-use)

`examples/language/english/iterate.vani`'s canonical pattern calls
`sum_vec(ref nums)` / `max_in_array(ref arr)` / `count_positives(ref mixed)`
— passing `ref` so the same Vec can be reused across multiple calls. The
following dialects' `iterate.vani` dropped the `ref` on at least one
repeated-use call site, causing "value 'v' was moved; cannot use after
move":

catalan, czech, danish, dutch, finnish, greek, hungarian, indonesian,
malay, norwegian, polish, romanian, slovak, swahili, swedish, turkish.

Fix: find the dialect's own `ref`-equivalent keyword (already correctly
used earlier in the same file, since only some call sites are missing it)
and add it at the missing call site(s). This is a mechanical, per-file
fix — diff the working vs. broken call site within the same file to see
the exact pattern each dialect already uses correctly elsewhere.
