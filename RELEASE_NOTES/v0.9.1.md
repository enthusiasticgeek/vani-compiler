# vāṇी v0.9.1 — 2026-08-07

Patch release. No new language features, no breaking changes — this release
consolidates roughly 70 bug fixes found and fixed across five separate sweeps
since v0.9.0 (2026-07-26 through 2026-08-07). It had been sitting unreleased
on `main` as `0.9.1-dev` while that work accumulated.

## Highlights

- **The single most impactful fix (BUG-110)**: both SSA backends — the
  default codegen path for most vāṇī programs — silently emitted fully
  *unchecked* arithmetic (no overflow, divide-by-zero, or shift-range
  guards), regardless of what the checker had determined was actually
  needed. A systemic safety hole affecting essentially every ordinary
  program, not a one-off edge case.
- **BUG-116**: the SSA path never lowered `requires` clauses at all — a
  violated precondition on the default backend hit a fully unguarded raw
  `sdiv`, a genuine silent safety hole rather than a cosmetic crash-message
  issue.
- `ensures` and `invariant` clauses gained real runtime enforcement
  (BUG-133/134), closing a long-standing asymmetry with `requires`: a
  clause the SMT solver can't fully decide now compiles clean with a
  runtime guard, instead of either being silently ignored or blocking the
  build outright.
- `vanic run` no longer masks a signal-killed child process as a bare exit
  code `1` (BUG-130) — it now correctly reports `128 + signal`, matching
  what a directly-executed binary's own shell would show.

## Bug fixes, by sweep

### Testing-matrix sweep — BUG-68 through BUG-80 (2026-08-02)

A 19-row sweep of nested/multi-level feature combinations and container x
intermediate/advanced feature nesting. 13 bugs, every one at a feature
*intersection* rather than in a single feature tested alone: SMT struct-field
modeling gaps, generic struct instantiation collisions, an LLVM PHI-node
crash, missing enum-payload zero-placeholder cases, and several C-backend
declaration-ordering bugs (struct fields, array parameters, SIMD-typed
fields). Full per-bug detail already in this file's own `### Fixed` section
below (written during that sweep).

### Feature-combination gaps sweep — BUG-81 through BUG-104 (2026-08-03–04)

A 49-row sweep of untested feature combinations across 11 categories: SIMD x
containers/generics, generics x concurrency handles (`Mutex<T>`/`Channel<T,N>`
with a still-generic `T`), SMT contracts x generics/enums, async/await x
everything else, `dyn` dispatch x generics, `try`/`?` x containers, thin-
coverage collections (graph/trie/skip-list actually running), FFI x generics,
a 3-way affine-ownership x generics x containers nesting, pattern-matching
depth x generics/enums, and boundary confirmations (expected-to-reject cases
nobody had actually run). Around 15 bugs found, nearly all tracing back to
the same root cause: a monomorphization or codegen "find every use of X"
walker that covered only a handful of the AST's shapes, not all of them —
the same pattern recurring at different call sites each time.

### Localfuzz-found bugs — BUG-105 through BUG-112 (2026-08-04–05)

Random-mutation fuzzing (`tools/localfuzz`) found 8 more bugs directly, most
notably BUG-110 (above) and BUG-109, a real bug in `echo_pool` initially
misdiagnosed as parallel/sort-library loading noise before being properly
root-caused.

### Bug-pattern audit — BUG-113 through BUG-125 (2026-08-05–06)

Organized by root-cause *pattern* instead of feature combination: read the
existing bug corpus for recurring shapes, then swept every other call site
that could plausibly share that shape. 13 bugs across 8 categories —
`requires`/`ensures` runtime-check consistency (including the SSA-`requires`
gap above), SSA-vs-tree safety-check parity, packed-bit `Vec<bool>` layout
gaps recurring in nested-Vec construction and struct-field reads, non-ASCII
identifier collisions, `HashMap<K, bool>` producing invalid LLVM IR, an
entire family of real ARM Linux cross-compile targets misclassified as
bare-metal (BUG-124), and AVX-512 code that failed to link on non-x86 targets
with no scalar fallback (BUG-125, found while verifying BUG-124's fix).

### Localfuzz backlog triage + new fixes — BUG-126 through BUG-140 (2026-08-07)

A full day's work: 15 bugs found and fixed directly (let-shadowing and
tuple-destructure codegen bugs, loop-carried overflow-elision unsoundness,
an async use-before-declare gap, several raw-`abort()`-instead-of-clean-
`exit(3)` sites, a signal-killed-child exit-code masking bug, an AVX-512
CPU-capability check, non-ASCII type names, `ensures`/`invariant` gaining
real runtime enforcement, a `u32` Vec-index LLVM IR bug, and the checker
never validating that a struct field / enum variant payload / function
signature's type actually exists), then a separate pass triaging a 77-item
backlog of never-reviewed localfuzz findings that had quietly accumulated
(42 no longer reproduced at all, 9 were a documented, permanent trap-code
convention rather than bugs, and the remainder were false positives from the
fuzzer mutating *test programs* — not the compiler — into broken control
flow). `parallel for` with a pathological loop range no longer silently
skips iterations on the C backend instead of trapping (BUG-140 — a genuine
GCC OpenMP undefined-behavior case, not a vāṇī-specific bug, but one the
compiler now guards against).

## Upgrade notes

- No breaking changes.
- If you cross-compile with `vanic build --target=arm-unknown-linux-gnueabi*`
  (or `gnueabihf`), BUG-124's fix changes that target family's
  classification from bare-metal to hosted Linux. This is a correctness fix,
  not a behavior change for any build that was actually working before —
  the prior misclassification made these targets fail to link entirely.
