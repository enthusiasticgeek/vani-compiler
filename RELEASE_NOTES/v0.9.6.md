# vāṇी v0.9.6 — 2026-08-24

A same-day follow-up to v0.9.5: fixes two real CI failures that
`scripts/release.py`'s local test run didn't catch (neither is part of
`cargo test --release --lib` / `--test run_end_to_end`, the two suites
that were run before cutting v0.9.5 — the full `cargo test --release`
across every integration test binary, and the separate ASan/LeakSanitizer/
UBSanitizer sweep, are both CI-only steps that surfaced these).

## Fixed

- **`step` keyword collision**: `tests/vtables_phase3.rs`'s
  `dyn_dispatch_emits_per_iface_typedefs_and_static_vtable` test defined
  an interface method literally named `step` — colliding with v0.9.5's
  own new `step` keyword. An earlier corpus sweep for this exact
  collision class only checked `examples/*.vani`, not vāṇी source
  embedded in `tests/*.rs`. Renamed to `advance`; swept every other
  `tests/*.rs` and `src/lib.rs` test source for the same shape (none
  found).
- **Missing `leak_sweep` baseline entry**: `examples/embedded/
  dma_mmio_trigger.vani` (added in an earlier session's DMA/
  scatter-gather tutorial content) was flagged as a new, un-baselined
  ASan SEGV. Confirmed not a compiler bug — the crash address is
  literally the file's own hardcoded STM32F4 DMA2 peripheral base
  address, the same "meant for real embedded hardware or QEMU, not
  native userspace execution" pattern the pre-existing `bare_metal.vani`
  baseline entry already documents. Added the missing entry.

## Upgrade notes

- No functional or breaking changes beyond v0.9.5 — this release exists
  solely to ship a green CI state. If you're already on v0.9.5 and
  haven't hit either issue above, there's nothing new to adopt.
