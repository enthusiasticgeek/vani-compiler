# vāṇī v0.2.0 — 2026-07-01

Major expansion of the cross-language translator tool: 57 supported
languages (up from 5), automatic SOV word-order rewriting, and LLM-backed
translation of comments, strings, and identifiers.

---

## Translator — `tools/vani_translate.py`

### 57 supported languages (was 5)

The `ALIASES` keyword table now covers 57 human languages across 12 script
families, with 2,016 reverse-lookup entries.

| Family | Languages added |
|--------|----------------|
| Indo-Aryan (Brahmic) | Bengali, Odia, Gujarati, Punjabi, Sinhala |
| Dravidian | Tamil, Telugu, Kannada, Malayalam |
| East Asian | Japanese, Korean |
| Southeast Asian | Thai, Vietnamese, Khmer, Burmese, Lao, Malay, Indonesian, Filipino |
| Middle Eastern / RTL | Arabic, Hebrew, Persian, Urdu, Pashto |
| Cyrillic | Russian |
| European (non-Latin) | Greek |
| European (Latin) | Spanish, French, German, Portuguese, Italian, Dutch, Polish, Turkish, Swedish, Norwegian, Danish, Hungarian, Czech, Slovak, Finnish, Romanian, Catalan |
| Caucasian | Armenian, Georgian |
| African | Swahili, Yoruba, Hausa, Amharic |
| Other | Tibetan, Cherokee, Mongolian |

Translation between any two of the 57 languages works directly — not only
through English.

### SOV word-order rewriting (20 languages)

Verb-final statement shapes (`return`, `print`, `assert`, `prove`) and
for-range loops (Devanagari family) are rewritten automatically when
translating to or from an SOV language. No flag needed.

```
English:   return total;             →  Hindi:   total लौटाओ;
Hindi:     i के लिए 0 से n तक {     →  English: for i from 0 to n {
```

SOV languages: Sanskrit, Hindi, Marathi, Bengali, Odia, Gujarati, Punjabi,
Sinhala, Tamil, Telugu, Kannada, Malayalam, Japanese, Korean, Urdu,
Persian, Pashto, Turkish, Mongolian, Tibetan.

### LLM translation of comments, strings, and identifiers

Pass `--llm BACKEND` to translate natural-language content via an LLM:

| Content | Without `--llm` | With `--llm` |
|---------|-----------------|--------------|
| `// line comments` | preserved verbatim | translated |
| `"string literals"` | preserved verbatim | translated |
| user-defined identifiers | preserved verbatim | translated (opt-in: `--translate-identifiers`) |

Three backends supported:

```bash
# Anthropic (claude-haiku-4-5-20251001 by default)
python3 tools/vani_translate.py file.vani --to hindi --llm anthropic

# OpenAI (gpt-4o-mini by default)
python3 tools/vani_translate.py file.vani --to hindi --llm openai

# Local Ollama — no API key
python3 tools/vani_translate.py file.vani --to hindi \
    --llm ollama --llm-model llama3.2 --llm-timeout 120
```

### Unicode tokeniser fix

`_is_word_char()` now recognises 27 Unicode script ranges, so non-ASCII
keyword tokens in Bengali, Tamil, Telugu, Kannada, Malayalam, Odia,
Sinhala, Gurmukhi, Gujarati, Arabic, Hebrew, Thai, Lao, Tibetan, Burmese,
Ethiopic, Georgian, Armenian, Cherokee, Mongolian, Greek, Cyrillic, CJK,
Hiragana/Katakana, Korean, and Khmer are correctly delimited without a
Unicode segmenter.

### Graceful fallback

Missing keyword entries in any language now fall back to the English
spelling instead of raising `KeyError`. This makes partial-coverage
language entries safe.

## Upgrade notes

- `SUPPORTED_LANGS` is now a tuple of 57 names. Any code that iterates
  it or tests membership still works unchanged.
- The `--from` / `--to` CLI choices are auto-generated from
  `SUPPORTED_LANGS`, so all 57 names are now valid arguments.
- No compiler (`vanic`) changes in this release.
