# vāṇी v0.8.1 — 2026-07-24

A bugfix-focused patch release: closes a same-release regression in async
ref-returning functions, two ref-related compiler crashes, a Kosh
same-project visibility gap, and four issues (BUG-1 through BUG-4) found
while building the `vani-bignum` package.

## What's new

- `f64_to_str_fixed` builtin — fixed-precision float formatting (Rust
  `{:.N}` / C `%.*f` equivalent).
- `sort_by` now works on any `Copy` `Vec<T>` element, not just `i64`/`f64`.

## Bug fixes

- Async fn returning `ref T` failed to compile (regression introduced
  earlier in this release cycle, caught by the full test suite before
  tagging).
- Two ref-related compiler crashes: a `ref` nested inside a tuple/generic
  return type, and printing a `ref` value — both now give clean
  diagnostics instead of crashing or emitting bad IR.
- `pub(kosh)` incorrectly rejected access from a sibling module in the
  same project; only cross-package access should be rejected (L23 phase 2).
- BUG-1: `file_read_line`/`stdin_read_line` were undefined at LLVM link
  time.
- BUG-2: `#[wcet]` under-counted struct-literal fields that call real
  functions.
- BUG-3: the C backend's Vec-bounds optimizer hint false-aborted on the
  "zip two different-length Vecs" pattern.
- BUG-4: `implement`/`methods on` blocks didn't parse `#[attr]`-prefixed
  methods.
- S-13/S-15 diagnostics pointed at the wrong source span.
- MATH-1: `sort()` on `Vec<i64>`/`Vec<f64>` crashed under `vanic run`/`test`
  (JIT path never linked the sort runtime).

## Upgrade notes

- No breaking changes.
