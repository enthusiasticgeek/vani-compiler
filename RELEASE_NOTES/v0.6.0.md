# vāṇी v0.6.0 — 2026-07-21

Fourteen new language/tooling features (generics, pattern matching, closures,
async, safety), five performance wins, a Kosh package-manager safety gate,
and three correctness fixes — the largest feature release since v0.5.0.

---

## New language features

### Generic trait bounds: inline syntax (G1)

`fn f<T: Iface>(x: T)` is now equivalent to the longer `fn f<T>(x: T) where
T is Iface` form — the colon-bound reads naturally at the declaration site
instead of trailing after the parameter list:

```vani
fn show<T: Describe>(x: ref T) -> i64 {
    return describe(x);
}
```

The monomorphizer enforces the bound exactly as it already did for `where`
clauses — a concrete type with no matching `implement Iface for T` is
rejected with the same diagnostic.

### Slice/vec destructure patterns in `match` (L1)

`[first, .., last]` patterns now match on `Vec<T>` and `[T; N]` scrutinees:

```vani
match xs {
    [] then 0,
    [only] then only,
    [first, .., last] then first + last,
}
```

Desugars to a length-guarded `if`/`let` chain — no new backend support
needed. Non-`Copy` element types are rejected with a clear diagnostic
(the desugaring would otherwise alias the same heap value into multiple
bindings).

### `#[repr(C)]` / `#[repr(packed)]` struct layout (L2)

Opt a struct into C-compatible or packed memory layout for FFI/embedded
work:

```vani
#[repr(C)]
struct Header { magic: u32, version: u16, flags: u16 }

#[repr(packed)]
struct WireRecord { id: u8, value: u32 }
```

### `select { await poll then binding { body } }` (L3)

Round-robin async select over multiple non-blocking poll expressions,
desugared entirely at check-time to a `while true` + per-arm `if` guard —
no new IR nodes:

```vani
select {
    await poll_a() then a { handle_a(a); break; },
    await poll_b() then b { handle_b(b); break; },
}
```

### Runtime integer overflow guards, with SMT elision (L4)

Integer arithmetic (`i8`..`i64`, `u8`..`u64`) now traps on overflow instead
of silently wrapping, closing an ASIL-D / DO-178C gap. The SMT discharge
pass elides the runtime check when a `requires` clause already proves the
operation safe, so provably-bounded arithmetic pays no runtime cost:

```vani
fn add_bounded(a: i64, b: i64) -> i64
  requires a >= 0 && a <= 1000 && b >= 0 && b <= 1000
{
    return a + b;  // guard elided — SMT proves no overflow
}
```

### Closures capture non-`Copy` (affine) bindings (L5)

Closures capturing `OwnedStr`, `Vec<T>`, etc. now take ownership at
creation time (move-capture / `FnOnce` semantics), with compiler-enforced
single-call and a scope-exit Drop guard that frees the captured
environment if the closure is never called.

### `Vec<bool>` packed bit-array (XL1)

`Vec<bool>` now stores 64 elements per `u64` word instead of one byte per
element — an 8x memory reduction with the same API (`push`, `set`, index,
etc.). No source changes needed in existing code.

### `vanic test` — built-in test runner (XL2)

Mark any function `#[test]` and run the whole suite with one command:

```vani
#[test]
fn addition_is_commutative() {
    prove 2 + 3 == 3 + 2;
}
```

```sh
vanic test src/lib.vani
```

Synthesizes a harness that calls every `#[test]` function and reports
pass/fail per test.

### `for await x in <Option<T> expr>` stream syntax (XL3)

Sugar over `while let`, for iterating a stream that yields `Option<T>`:

```vani
for await item in next_chunk() {
    process(item);
}
```

### Multi-pass generic monomorphization (XL4)

Nested generic call chains (`f<T>` calling `g<T>` calling `h<T>`) now
monomorphize correctly — the monomorphizer iterates a worklist until no
new specializations are discovered, instead of a single pass that missed
specializations only reachable from an already-generated one.

### `Atomic<T>` gains `f64` (G3)

`Atomic<f64>` now supports `new`/`load`/`store`. `atomic_fetch_add` on
`f64` is explicitly rejected (hardware `atomicrmw fadd` has narrow ISA
support — safer to error than silently degrade).

### `clone_at` on `Vec<(i64, OwnedStr)>` (G2)

Fixes a "not yet supported in tree-LLVM" panic and a missing SSA-LLVM code
path for `clone_at` on vectors of tuples containing `OwnedStr` fields —
both backends now deep-clone correctly.

### Kosh package publishing: `vanic audit-safety` + `vanic publish` gate

New `vanic audit-safety <path> [--format=text|json]` verifies
`#[bounded_stack]`/`#[wcet]` coverage wherever a function is actually
*eligible* for it (not blanket 100% attribute presence — fn-pointer
params and unbounded loops/recursion are legitimately exempt). `vanic
publish` now runs this automatically and refuses to publish on any gap,
with `--allow-partial-safety-coverage` as an explicit escape hatch. See
[Sec.16 — Kosh Packages](https://enthusiasticgeek.github.io/vani-compiler/intermediate/16_packages.html#safety-coverage-gate).

### `file_open` gains a required `buffered: bool` argument

```vani
let f: FileHandle = file_open("out.log", "w", false);  // unbuffered
```

`buffered: false` calls `setvbuf(..., _IONBF, 0)` so writes reach the OS
immediately — useful for crash-safe logging. **Breaking**: existing
2-argument `file_open` calls are now a compile error; add the third
argument (`true` reproduces the old always-buffered behavior).

## Performance

- **Sort: pdqsort replaces Lomuto quicksort** — branchless block
  partitioning, Tukey ninther pivot selection, heapsort fallback,
  insertion sort for small arrays. 1M-integer sort: 97.1ms → 65.9ms
  (32% faster).
- **Sort: pattern detection for sorted/reverse-sorted input** — O(n)
  passes skip partitioning entirely on structured data.
- **Sort: AVX-512 bitmask scan in the block-partition hot path** —
  ~5% further improvement on top of pdqsort.
- **Parallel `for … reduce`: persistent pthread pool** replaces
  per-invocation thread spawn. 50M-element parallel sum: 197.2ms →
  125.8ms (36% faster) — now faster than Rust's equivalent.
- **`getelementptr inbounds` on all Vec/Array GEPs** in the SSA-LLVM
  backend, enabling stronger alias analysis and auto-vectorization.
  Sieve benchmark: 15.4ms → 12.6ms (18% faster) — now the fastest of
  vāṇī/C/C++/Rust on this benchmark.

## Fixes

- **`vanic run` misreporting a failed `assert` as a stack overflow** —
  `abort()`'s `SIGABRT` could trigger LLVM's crash handler mid-fault on
  Windows; switched to `exit(3)`, matching `vanic build`'s AOT behavior.
- **`vanic publish`/`vanic vendor` silently dropping path dependencies**
  — the tarball builder skipped any directory named `vendor/`, which
  meant a package's own vendored dependencies never made it into its
  published tarball.
- **`sha256_file` corrupting checksums on Windows** — GNU coreutils
  prefixes its output with `\` when the filename contains a backslash
  (every native Windows path); the naive whitespace split glued it onto
  the hash, silently corrupting every checksum computed by `vanic
  publish`/`vanic add` on Windows.

## Upgrade notes

- **Breaking**: `file_open(path, mode)` is now `file_open(path, mode,
  buffered: bool)`. Existing 2-argument calls are a compile error; pass
  `true` to keep the previous always-buffered behavior.
- No other syntax, IR, or ABI breaking changes.
- `vanic publish` now hard-blocks on incomplete `#[bounded_stack]`/
  `#[wcet]` coverage. If you publish Kosh packages, run `vanic
  audit-safety <entry>` before your next publish, or pass
  `--allow-partial-safety-coverage` if you're not ready to fully
  annotate yet.
