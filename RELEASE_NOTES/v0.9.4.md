# vāṇी v0.9.4 — 2026-08-17

Consolidates 15 bug fixes (BUG-185 through BUG-199) plus two long-standing
limitations closed (L28, L30) since v0.9.3 (2026-08-12), alongside a
genuinely feature-heavy batch for a `0.9.x` release: `detach()` for
`Task<R>`, `cancel <name>;` for interrupting real blocking syscalls,
descending `downto` loops rolled out to all 62 dialects, the compiler's
first-ever non-fatal warnings (plus `--deny-warnings`), inline `print`
format specs (`print x:03;`), a five-phase `vanic test` hardening pass,
and a new `tools/backend_crosscheck.py` corpus-wide backend-agreement
tool that found a real bug on its first run. See `docs/TODO_CURRENT.md`
for full per-bug detail; this file groups by theme.

## Highlights

- **`detach()` for `Task<R>`**: a second, mutually-exclusive way to
  consume a spawned task handle — the thread keeps running independently
  instead of being waited on with `join`. Five new real-world examples
  (barrier rendezvous, a cancellable job queue, arena batch parsing,
  parallel-reduce, a background heartbeat) exercise it end-to-end.
  Building them surfaced three real, previously-unknown compiler bugs
  (BUG-188/189/190), documented but deliberately not fixed this pass —
  none were on the critical path for working examples.
- **`cancel <name>;`**: the other half of the cancellation story —
  interrupts a `task` thread genuinely blocked inside a real syscall
  (`tcp_accept`, `tcp_recv`) via `pthread_kill` + `EINTR` on POSIX
  (Windows: `CancelSynchronousIo`; macOS: shares the POSIX path).
  Building this for real (not just emitting IR) caught two live bugs:
  `signal()` silently installing `SA_RESTART` on this glibc target
  (confirmed via `strace`, defeating cancellation entirely until fixed),
  and a heap buffer overflow from a stale ctx-size formula.
- **Real compiler warnings, at last**: every `Diagnostic` used to be an
  unconditional hard error — there was no way to flag something
  suspicious without either breaking real, intentional programs or
  staying silent. New `Severity::Warning` plus five checks (to/downto
  bounds-direction, self-assignment, unused var/param, identical
  if/else branches) and a `--deny-warnings` CI-strictness flag. Two
  bugs in the *implementation* of the new checks were caught by running
  them against the full 1049-file corpus, not by unit tests alone.
- **`downto` reaches all 62 dialects**: the descending-loop keyword
  shipped English-only in v0.9.3's window; this release completes the
  keyword-parity sweep (matching the BUG-170 methodology) across every
  dialect that already has `to`/`until`.
- **`tools/backend_crosscheck.py`**: a new CI-wired tool that runs every
  passing example through both backends and asserts matching exit
  codes. Its first-ever run found a real divergence (BUG-192's sibling):
  overflow/divide-by-zero/shift traps exited clean (3) on LLVM but
  `abort()` (134) on C — six call sites fixed to agree.
- **`vanic test`, five phases (B–F of the #188/#189 audit)**: `--filter`,
  `#[should_panic]`, parallel execution by default (`--test-threads=N`
  to override), package-level default discovery (`vanic test` with no
  args inside a Kosh package), and `assert_eq_i64/f64/bool/str` —
  the single most-reached-for convenience missing from plain `assert`.
- **Inline print format specs**: `print x:03;` / `print y:.2;`,
  Rust-`{:03}`/`{:.2}`-style width/precision at the call site. Required
  a new lexer token (`TokenKind::FormatSpec`) since the existing token
  stream had already lost the source spelling needed to distinguish
  `:03` from `:3`.

## Bug fixes, by theme

### LLVM backend `ctx.current_block` staleness (BUG-185, BUG-196)

The same bug class recurred twice this release, both times a branch/merge
site that forgot to update `ctx.current_block` afterward, so any later
phi-node-consuming codegen in the same function captured the wrong
predecessor block and `lli` rejected the module ("PHI node entries do not
match predecessors!"):

- **BUG-185**: `print`-ing a `bool` merges two branches back together but
  never pointed `ctx.current_block` at the merge block — any later
  `vec_fill`, `if`-expression, or `while` loop in the same function could
  inherit the stale predecessor. `print true;` alone, followed by any
  phi-consuming construct, was enough to trigger it.
- **BUG-196**: `while`-loop codegen never updated `ctx.current_block` when
  opening its header/body blocks (unlike the loop's exit block, already
  fixed earlier). Any short-circuit `&&`/`||` as the loop condition or
  inside the body recorded the wrong PHI predecessor. Reproduced on
  pre-existing Newton-iteration-style functions; found while validating
  an external package's numerical code, not a fuzzer.

### SMT stale-fact soundness (BUG-198, BUG-199)

Direct continuations of v0.9.3's BUG-181/182/183 series — the same
"a fact stays true in the checker's model after the program state it
described has changed" shape, at two more sites:

- **BUG-198**: a `mut ref` Vec mutation (`pop(mut ref zs)`,
  `push(mut ref zs, v)`) never invalidated stale length/element facts
  about that Vec, letting the bounds-check elision pass "prove" an
  already-stale index in-bounds. Confirmed exploitable: a raw unguarded
  out-of-bounds read on the C backend, printing a stale popped value
  instead of trapping — AddressSanitizer doesn't catch this shape (the
  read is within allocated capacity, just past logical length).
- **BUG-199**: more severe — a struct field mutated via `FieldAssign`
  left a stale `<obj>__<field> == <original-value>` fact in place
  forever, so a later `if field == new_value { prove field == old_value; }`
  produced a directly contradictory fact base, from which *any* claim
  becomes vacuously "provable." A real path to proving arbitrary false
  claims, not just failing to prove true ones.

### Backend exit-code / trap-message parity (BUG-192, BUG-194)

- **BUG-192**: two independent gaps sharing one symptom (correct exit
  code, but empty stdout/stderr) — a bare `assert expr;` with no custom
  message skipped the trap-message print entirely on tree-LLVM (SSA-LLVM
  already had this fixed), and `parallel for`'s internal overflow guard
  called a bare `exit(3)` never wired to any diagnostic at all.
- **BUG-194**: bounds-check traps exited `abort()` (134) on the C backend
  but `exit(3)` on LLVM for the identical program — the same class #191
  fixed for overflow/divide-by-zero/shift, on the wrong assumption
  bounds-check was already consistent. It wasn't: LLVM's bounds helper
  had used `exit(3)` since BUG-108/162, predating #191; only the C
  backends' bounds helpers were never migrated. Fixed across 7 call
  sites (tree-C's shared helper plus 4 method-specific messages,
  SSA-C's 4 inline guards).

### Other correctness fixes

- **BUG-186**: `task`/`join` inside *any* loop body crashed `vanic check`
  outright — the bounds-elision pass's internal loop-reassignment walker
  called into a substitution path that assumed task/join could never
  appear there, an assumption that was simply false. 100% reproducible,
  not a corner case.
- **BUG-187**: `implement` blocks were never checked against their
  interface's declared parameter *types* (only count and return type).
  A mismatched type produced silently wrong, backend-dependent output
  through a `Vec<dyn Iface>` vtable call — a real, live divergence, not
  hypothetical (found via localfuzz).
- **BUG-191**: `Vec<Mutex<T>>`/`Guard<T>`/`RwLock<T>`/`ReadGuard<T>`/
  `WriteGuard<T>` all collapsed onto one C typedef regardless of `T` —
  the same collapse-bug shape `Box<T>`/`Atomic<T>`/`Channel<T,N>` were
  already protected against, never extended to this family. Confirmed
  exploitable: two different `T`s in the same program produced an
  incompatible-pointer-type compile error.
- **BUG-193**: a fresh, never-bound `OwnedStr` passed as an argument to
  an *ordinary* user-defined function had no owner to free it —
  BUG-159/160/161 fixed the identical shape for specific builtin call
  sites only; this closes the general case. A first draft introduced a
  real double-free regression, caught by the corpus-wide ASan sweep
  (not the plain test suite) before it shipped.
- **BUG-195**: a same-scope shadowed `let` inside a match-arm/`try`-desugar
  block body produced a C compile error ("redefinition of...") — the
  block-expression checker path never checked for shadowing the way the
  regular function-body handler already did. Would also have leaked a
  shadowed non-Copy value's heap allocation.
- **BUG-197**: `vanic publish` could silently drop a registry-index entry
  under rapid repeated publishes — the "current content" fetch went
  through a CDN URL that can lag several minutes behind a just-pushed
  commit, so a second publish within that window overwrote the first
  publish's entry with a stale base. Fixed by decoding the metadata
  response's own content field directly, eliminating the CDN read path.
- **L28**: float-to-int `as` casts (`f32`/`f64` → any integer type) were
  unchecked on both backends — real C-standard UB on out-of-range/NaN
  input that diverged in *observable exit code* (255 on C, 0 on LLVM)
  rather than just agreeing on a wrong answer. Now a defined runtime
  range check traps with "float-to-int cast out of range" and `exit(3)`
  on all four backend emission paths.
- **L30**: added `tcp_buf_byte_at(i: i64) -> i64`, mirroring
  `str_byte_at`'s shape, so `tcp_recv`'s received bytes are finally
  inspectable from vāṇī code instead of only usable via a
  message-length-encoding workaround.

## Language & tooling additions

- **`downto`** for descending `for` loops, rolled out to all 62 dialects
  this release (English-only in the prior window). Closes the gap noted
  in `docs/v1_limitations.md`'s L29; also closed a real pre-existing gap
  where `TokenKind::DownTo` was missing from the script-purity gate.
- **Compiler warnings** (`Severity::Warning`, non-fatal): to/downto
  bounds-direction contradiction, self-assignment, unused variable/
  parameter, identical if/else branches. `--deny-warnings` escalates any
  warning to a build failure (rustc `-D warnings` / gcc `-Werror`
  equivalent).
- **`detach()`** for `Task<R>` and **`cancel <name>;`** — see Highlights.
- **`\xHH` hex byte escape** in string literals (00–7f only, matching
  Rust's own `&str` restriction), for cases like ANSI terminal escape
  codes that have no other safe way to appear in source.
- **Inline print format specs** (`print x:03;` / `print y:.2;`) — see
  Highlights.
- **Cross-language "did you mean" parser hints**: C-style
  `for (init; cond; incr)`, old-style `for i in LOW..HIGH` ranges,
  Pascal-style `for i = LO to HI`, `foreach`, `do { } while (...)`,
  `switch`/`case`, `let mut`, bare `var` declarations, `elif`/`elseif` —
  each a zero-consumption lookahead hint pointing at the real vāṇī
  syntax instead of an unhelpful downstream parser/checker error. Found
  and fixed a real infinite-loop bug in the parser's error-recovery path
  while building this.
- **`vanic test` phases A–F**: `#[test]` files that also have a real
  `fn main` no longer silently skip harness mode; `--filter=<substring>`;
  `#[should_panic]`; parallel test execution by default
  (`--test-threads=N` to control it); package-level default discovery
  (`vanic test` with no path args, inside a Kosh package); and
  `assert_eq_i64/f64/bool/str` builtins.
- **`tools/backend_crosscheck.py`**: new CI-wired corpus-wide backend
  exit-code agreement checker — see Highlights.
- **Build-time caching**: `sort_runtime.c`/`parallel_runtime.c`'s
  embedded C helpers are now cached by a content+toolchain+host hash
  instead of recompiled on every single build (~66% wall-time reduction
  on a typical single-file build, fails open to a full correct recompile
  on any cache-validity doubt).
- **`vani_translate.py`** (the dialect-translation dev tool, not the
  compiler itself) was silently broken for ~24% of dialects — its
  hand-maintained keyword-alias table had drifted from `src/lexer.rs`'s
  real tables (the same staleness shape as BUG-173's `src/lsp.rs`).
  Now regenerated mechanically from `lexer.rs` via a new
  `tools/regen_vani_translate_keywords.py`, with a permanent regression
  suite (`tools/test_vani_translate.py`) wired into CI.
- **`install.ps1`** now detects Windows architecture instead of
  hardcoding `x86_64`.

## New examples

Terminal tic-tac-toe (two human players, then an AI opponent, then a
timed variant using `task`/`join`/`Atomic<T>`, then a second
implementation using `task`/`cancel` over real TCP), five `detach()`
real-world examples (barrier rendezvous, job-handle cancellation, arena
batch parsing, parallel-reduce, background heartbeat), an RTOS
priority-inversion / priority-ceiling-protocol simulation (the classic
1997 Mars Pathfinder bug and its textbook fix), and a real, CI-checked
Make/CMake/Meson/Ninja build-system example matching the build-systems
tutorial chapter.

## Documentation

A large tutorial-accuracy pass this release, mostly triggered by asking
whether the compiler tutorial explains its own acronyms and *why* each
compiler stage exists rather than just describing it: expanded SMT's
first-use definition with a glossary link and a "why a solver, not just
testing" explanation; fixed stale claims across 25 primer chapters
falsely asserting "no compiler code" backs a given concept; fixed a
false "intuition primer chapters contain no code" claim in the intro;
fixed stale 57-language and example-count claims; fixed mojibake and a
corrupted logo alt text; documented the now-enforced implement/interface
parameter-type match (BUG-187); documented how SMT verification handles
recursion/reentrancy; and added a new capstone chapter combining
`Pollable`/`Executor`, cooperative `CancelToken` cancellation, and
real-thread `cancel <name>;` in one worked example.

Also root-caused and documented **L31**: a `detach()`'d task still
running when `main` returns can segfault under `vanic run`'s default
LLVM `lli`-JIT path — confirmed to be a bug in upstream `lli`'s own
teardown (the identical program via `vanic build`, real AOT compilation,
runs correctly every time), not something vāṇī's own emitted IR can fix.
Documented as a known limitation: use `vanic build` or
`vanic run --backend=c` if a `detach`'d task might outlive `main`.

## Upgrade notes

- No breaking changes.
- Programs relying on unchecked float-to-int cast UB (L28) now trap
  cleanly with `exit(3)` instead of producing backend-dependent garbage
  or a diverging exit code. This can only ever change behavior that was
  already undefined.
- A handful of style warnings (self-assignment, unused var/param,
  identical branches, backwards to/downto ranges) may now print to
  stderr on programs that previously compiled silently. None of these
  fail the build unless `--deny-warnings` is passed explicitly.
- `assert`/overflow/divide-by-zero/shift/bounds trap exit codes are now
  fully consistent (`exit(3)`) across all four backend emission paths;
  code that specifically depended on the C backend's old `abort()`
  (SIGABRT, exit 134) behavior for any of these traps will observe a
  different exit code (this was already the LLVM backend's behavior).
