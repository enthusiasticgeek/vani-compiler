# vāṇी v0.7.0 — 2026-07-22

Kosh package dependencies get real namespacing — the headline feature —
plus the infrastructure work needed to ship it safely: transitive
dependency resolution, diamond-dependency deduplication, circular-dependency
detection, a real lockfile, and a migration diagnostic. Also fixes a
release-pipeline bug that meant every past tagged release shipped with no
downloadable binaries.

---

## New: Kosh package dependency namespacing

Every `[deps]` package is now compiled inside its own namespace. Call its
functions (and any exported struct types) with the package-name prefix:

```vani
// vani.toml: [deps] matrix = { path = "./vendor/matrix" }
let y: Vec<f64> = matrix::mat_solve(ref a, ref b, n);
```

or bring a name into scope the usual way:

```vani
use matrix::mat_solve;
let y: Vec<f64> = mat_solve(ref a, ref b, n);
```

This closes a real gap: previously every `[deps]` package's functions
landed in one flat global table shared with every vāṇī builtin and every
other dependency. A package defining `fn abs(...)` was an unrecoverable
compile error the moment it collided with the builtin `abs` — or with any
other package's `abs`. Now they're in separate namespaces and can never
collide.

### Dependency resolution is now fully transitive, and diamond-safe

A dependency of a dependency is resolved automatically — no more silent
missing-function errors when two packages you depend on each vendor their
own copy of a third. Two paths to the same `(name, version)` package
resolve to **one** compiled copy:

```
your-project
├── pkg_a  →  shared (v1.2.0)
└── pkg_b  →  shared (v1.2.0)      # same package, resolved once
```

A genuine version conflict (two different versions of the same package
name reachable in one graph) is a hard compile-time error naming both
paths, rather than a confusing partial failure.

### Circular dependencies are rejected with a full cycle trace

```
error: circular dependency detected in the Kosh dependency graph:
  pkg_a -> pkg_b -> pkg_a
```

Reuses the same Tarjan SCC algorithm that backs `vanic acyclicity`'s
function-call-graph analysis, applied to the package graph instead.

### Migration diagnostic

An unqualified call that would resolve to a dependency's function gets a
targeted suggestion instead of a bare "unknown function" error:

```
error: unknown function 'mat_zeros'
  help: 1. No function named `mat_zeros` is visible at this call site -- but `matrix::mat_zeros` exists.
  help: 2. Did you mean `matrix::mat_zeros`? ...
```

### `vani.lock` records the full resolved graph

Not just direct `[deps]` entries — every transitively-resolved package
gets a `[[package]]` entry, marked `direct = true`/`false`.

### `vanic add` sanitizes non-identifier package names

A `[deps]` key is now a namespace identifier, so it must be a valid vāṇī
identifier. `vanic add some-hyphenated-pkg` now writes it into `[deps]` as
`some_hyphenated_pkg` automatically (and tells you it did), instead of
generating a `vani.toml` that fails to compile.

Full design and verification writeup:
[`docs/kosh_namespacing_design.md`](https://github.com/enthusiasticgeek/vani-compiler/blob/main/docs/kosh_namespacing_design.md).

## Fixed: release pipeline never attached binaries

Every past tagged release — verified back through v0.4.0 — reported success
but shipped with **zero downloadable binaries**. `actions/download-artifact@v4`
nested each platform binary into a same-named subdirectory, and the
"flatten" step's `mv` moved each file back into its own parent directory, a
self-referential no-op. Fixed with `merge-multiple: true`. This release's
binaries are attached correctly.

Also added asset retention: only the 3 most recent releases keep their
binaries attached going forward (release pages and notes are untouched for
every version — only the large files are pruned from older ones).

## Known limitation newly documented: `pub(kosh)` is not enforced

While correcting the namespacing docs, found that `pub(kosh)` — intended
as a `pub(crate)`-equivalent visibility tier — has never actually been
enforced by the checker; it behaves identically to `pub` everywhere,
including across a real Kosh package boundary. This predates this release
and isn't something the namespacing work introduced. Documented as
[L23](https://github.com/enthusiasticgeek/vani-compiler/blob/main/docs/v1_limitations.md)
in the known-limitations catalog. Write `pub(kosh)` to document intent if
you like; it doesn't yet restrict anything `pub` doesn't.

## Upgrade notes

- **Breaking**: if your project has `[deps]` entries, every call site that
  used to call a dependency's function unqualified now needs the
  `pkgname::` prefix (or a `use pkgname::item;` import). The compiler's
  "did you mean `pkgname::item`?" diagnostic (above) tells you exactly
  what to change at each call site.
- All 12 published packages in the Kosh math ecosystem (`kosh-index`) have
  already been migrated and republished — `vanic add`/`vanic update` will
  pull the qualified-syntax versions automatically.
- No syntax, IR, or ABI breaking changes beyond the `[deps]`-calling-convention
  change above.
