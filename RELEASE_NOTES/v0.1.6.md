# vāṇī v0.1.6 — 2026-06-21

Bare-metal / cross-compilation arc — all 5 gaps closed. `--target`,
`--no-std`, `#[no_mangle]`, `#[link_section]`, and narrow MMIO builtins
(u8/u16) ship together. L19 in `docs/v1_limitations.md` is fully resolved.

---

## What ships in v0.1.6

| Feature | Summary |
|---|---|
| `--target=<triple>` | Passes `--mtriple=<triple>` to `llc`; selects cross-linker via `$CROSS_CC` or `<triple>-gcc`; bare-metal triples suppress libc/OpenMP/pthread flags |
| `--no-std` (C backend) | Suppresses all `#include <std*.h>`; emits a minimal typedef block (`uint8_t`, `int64_t`, `size_t`, `uintptr_t`, `NULL`); auto-activates for bare-metal triples |
| `#[link_section = "..."]` | Emits `__attribute__((section(...)))` in C and `section "..."` on the LLVM IR `define` line |
| `#[no_mangle]` | Suppresses the `intent_` prefix and Unicode mangling in both backends; linker scripts can reference the bare vāṇी function name |
| `mmio_read_u8` / `mmio_write_u8` | 8-bit volatile MMIO builtins (joins existing `mmio_read_u32`/`mmio_write_u32`) |
| `mmio_read_u16` / `mmio_write_u16` | 16-bit volatile MMIO builtins |
| QEMU user-mode run | `vanic run --target=<linux-triple>` transparently invokes `qemu-<arch>-static` (or `$QEMU_<ARCH>`) |

## `--target` and cross-compilation

```sh
# Cross-compile for 32-bit ARM bare-metal (Cortex-M)
vanic build --target=thumbv7m-none-eabi src/main.vani

# Cross-compile and run in QEMU user-mode (Linux target)
vanic run --target=aarch64-linux-gnu src/main.vani
```

When the triple contains `none` or `eabi` (bare-metal pattern), the
compiler automatically:
- Passes `--no-std` to the C backend
- Omits `-lm`, `-lpthread`, `-fopenmp` from the linker invocation
- Selects the cross-linker from `$CROSS_CC` if set, falling back to `<triple>-gcc`

## `#[no_mangle]` and `#[link_section]`

These attributes let vāṇी functions sit at addresses that linker scripts
control — essential for interrupt-vector tables, reset handlers, and
memory-mapped initialization code.

```vani
#[no_mangle]
#[link_section = ".text.reset_handler"]
fn reset_handler() -> i64 {
    // This symbol appears in the binary as `reset_handler`,
    // placed in the `.text.reset_handler` linker section.
    return 0;
}

#[no_mangle]
#[link_section = ".vector_table.exceptions"]
fn default_exception_handler() -> i64 {
    return 0;
}
```

## New MMIO builtins

```vani
// 8-bit register read / write
let val: u8 = mmio_read_u8(0x4000_0000);
let _   = mmio_write_u8(0x4000_0001, 0xFF);

// 16-bit register read / write
let reg: u16 = mmio_read_u16(0x4000_0002);
let _    = mmio_write_u16(0x4000_0004, 0x1234);
```

All four new builtins emit a `volatile` load/store in both the C backend
(`*(volatile uint8_t *)addr`) and the LLVM backend (`load volatile i8, …`).

## `--no-std` for the C backend

```sh
vanic emit --backend=c --no-std src/main.vani
```

The emitted C file contains no `#include` lines — only a minimal preamble:

```c
typedef unsigned char      uint8_t;
typedef unsigned short     uint16_t;
typedef unsigned int       uint32_t;
typedef unsigned long long uint64_t;
typedef signed long long   int64_t;
typedef unsigned long      size_t;
typedef unsigned long      uintptr_t;
#define NULL ((void*)0)
```

This is suitable for freestanding targets where no libc is present.
