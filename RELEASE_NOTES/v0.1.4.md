# vāṇी v0.1.4 — 2026-06-20

Compiler fixes for two mixed-feature edge cases, plus a full broken-link
sweep of the tutorial site.

---

## Non-Copy elements in tuples — now fully supported

Previously, `(OwnedStr, i64)` and similar tuples containing non-Copy
types were rejected with *"v1 tuples are Copy-only"*. v0.1.4 removes
that restriction across both backends.

### What changed

| Layer | Change |
|---|---|
| `ast.rs` | `Type::Tuple.is_copy()` returns `false` unless ALL elements are Copy |
| `checker.rs` — tuple construction | Moving a non-Copy `Var` into a tuple literal marks the source binding as moved — prevents double-free |
| `checker.rs` — LetTuple destructure | `let (s, n) = pair` marks `pair` as moved so scope-exit Drop doesn't also free the same heap data |
| `backend_c.rs` | `TypedStmt::Drop` for `Type::Tuple` walks fields via `emit_struct_field_drops` using the `_0`, `_1`, … naming convention |
| `backend_llvm.rs` | `TypedStmt::Drop` for `Type::Tuple` emits per-element GEP + `free` for `OwnedStr`, `Vec<T>`, and `Box<T>` fields |

Regression test: `examples/edge_cases/mix_tuple_non_copy.vani` — both
backends produce output `42` with clean exit.

---

## `Box<T>` as enum variant payload — now fully supported

Previously `Option<Box<T>>` and any enum with a `Box<T>` payload were
rejected at the checker's payload admit-list.

### What changed

| Layer | Change |
|---|---|
| `checker.rs` | Payload admit-list extended with `Type::Box(_)` |
| `backend_c.rs` — scope-exit drop | Added `Some(Type::Box(inner))` arm handling `Box<dyn Iface>`, `Box<Vec<T>>`, `Box<OwnedStr>`, and scalar `Box<T>` |
| `backend_c.rs` — per-slot drop | Same arm in `c_element_per_slot_drop` |
| `backend_llvm.rs` — enum drop | Added `"box"` heap-kind case |

Regression test: `examples/edge_cases/mix_box_enum_payload.vani` — both
backends produce output `42` with clean exit.

## Tutorial site — broken links fixed (19 files)

A full audit of `tutorials/src/` found three categories of broken links,
all repaired in this release:

| Category | Files | Count |
|---|---|---|
| Wrong GitHub repo (`anthropics/claude-code` → `enthusiasticgeek/vani-compiler`) | 14 | ~15 links |
| Wrong relative paths (intermediate → advanced without `../advanced/`) | 3 | 5 links |
| Ellipsis placeholder URLs (`github.com/...`) | 2 | 4 links |

The `unsafe.md` references in intermediate primers now point to the
correct absolute GitHub URL instead of a non-existent relative path.

The deploy-tutorials GitHub Actions workflow rebuilds the live site at
<https://enthusiasticgeek.github.io/vani-compiler/> automatically on push.

## Installation

```sh
# via crates.io
cargo install vani

# Linux / macOS
curl -fsSL https://raw.githubusercontent.com/enthusiasticgeek/vani-compiler/main/install.sh | sh

# Windows (PowerShell)
irm https://raw.githubusercontent.com/enthusiasticgeek/vani-compiler/main/install.ps1 | iex
```

Pre-built binaries for Linux x86_64/aarch64, macOS x86_64/aarch64, and
Windows x86_64 are attached to this release.
