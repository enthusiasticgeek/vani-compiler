# vāṇी v0.9.2 — 2026-08-11

Patch release. Consolidates roughly 38 bug fixes (BUG-141 through BUG-178)
found across several audit rounds and a systematic ASan/LeakSanitizer sweep
of the full example corpus, plus one small language feature (positional
`break`/`continue` targets), since v0.9.1 (2026-08-07 through 2026-08-11).

## Highlights

- **BUG-167 (soundness)**: the SMT identifier sanitizer collapsed every
  non-ASCII character to the same single underscore, so two distinct
  variables spelled with different non-Latin scripts could alias into one
  SMT symbol — a real proof-soundness bug, not a cosmetic display issue.
  Fixing it exposed a second, previously-masked gap (BUG-168): both
  backends were splicing raw non-ASCII source identifiers directly into
  target-language symbol names at several call sites instead of mangling
  them.
- **The leak/UAF sweep (BUG-153–161)**: a systematic ASan/LeakSanitizer run
  over the full example corpus found a real leak and a general
  use-after-free, then traced the same underlying shape — a fresh
  `OwnedStr` narrowed to a `Str` view that outlives the owner — to four
  more independent call sites over the next two days: closures, struct
  field assignment, bare function-call arguments, and several `HashMap`/
  `Trie` key operations. This class of bug is now closed everywhere it was
  found; CI gained a permanent ASan/LSan/UBSan corpus sweep so future
  regressions of this shape get caught automatically.
- **BUG-171 (widespread)**: a native-speaker-style linguistic review across
  ~40 language dialects turned up real word-choice mistakes and
  cross-dialect keyword contamination, but also an unrelated, much bigger
  find: a `vec(0)`-is-not-an-empty-vec bug affecting 46 example files
  across the corpus.
- **Positional `break`/`continue`** (BUG-176): `break inner` / `outer` /
  `middle` now resolve by loop-nesting depth instead of requiring a
  declared label — closing a feature gap that three pre-existing
  `examples/edge_cases/mix_break_*.vani` files had been silently testing
  against code that was never actually implemented.

## Bug fixes, by theme

### Leak / use-after-free sweep — BUG-153 through BUG-161 (2026-08-09–10)

A dedicated ASan/LeakSanitizer sweep of the full example corpus (BUG-153/
154) found a genuine leak and a genuine use-after-free on the first pass.
The next two days traced the same root shape — a fresh, owning `OwnedStr`
narrowed to a borrowing `Str` view whose lifetime the checker didn't
actually tie to the owner's — to independent recurrences: a closure
returned from (or merely called inside) a function leaked its captured
environment struct (BUG-155/156); a struct field assignment (BUG-157/158)
and a bare function-call argument (BUG-159) could each dangle or leak
depending on the exact call shape, confirmed to recur inside the async
state-machine transform as well as ordinary sync code; and the identical
escape vector recurred narrowly in `hashmap_get`/`contains_key`/`remove`
and every `Trie` key operation (BUG-160/161). CI now runs the ASan/LSan/
UBSan sweep on every push so this bug class can't silently regress.

### Backend safety / consistency — BUG-141 through BUG-149, BUG-162 through BUG-164

Two audit rounds targeting missing bounds/overflow guards and backend
message parity: `Box<dyn Iface>` forward-declaration ordering plus a
shift-amount width mismatch (BUG-146), `clone_at()` (BUG-147),
`vec_remove_at()` (BUG-148), and fixed-size array indexing on tree-LLVM
(BUG-149) each had a genuine unguarded out-of-bounds access on at least one
backend. Separately: an `i64`-narrower `set()`/`set_mut()` call producing a
mismatched LLVM call signature (BUG-141), a top-level `const` colliding
with a same-named parameter in the checker's root scope (BUG-142), a
nonexistent `.len` field reference in tree-C for fixed-array `while`-loop
indexing (BUG-143), interface methods and local `let` annotations missing
an existing type-existence check (BUG-144), and an unguarded overflow in
LLVM `parallel for`'s GOMP trip-count arithmetic for any reduction operator
(BUG-145). Later in the cycle: both LLVM runtime safety guards exited
silently on trap instead of printing a message like the C backend already
did (BUG-162), a struct field of type `Vec<T>` had NO bounds check on its
index read on tree-LLVM (BUG-163), and SSA-C rejected *any*
`Vec<T>`-returning function outright, silently falling the whole enclosing
program back to the slower tree-C path (BUG-164).

### Soundness / identifier localization — BUG-166 through BUG-170

BUG-166 fixed mojibake-corrupted `async`/`await` spellings in 4 languages,
zero non-English `eprint` coverage, and 2 dialect-purity violations. Fixing
those surfaced BUG-167 (the SMT sanitizer aliasing bug, above) and BUG-168
(both backends' raw-identifier-splicing gap), both closed the same day.
Two structure-keyword parity rounds (BUG-169/170) then swept the
India-language and "global language" dialect tables — 59 of 60+ dialect
functions were missing at least one keyword — and added a SOV-vs-SVO
grammar consistency check plus a Pashto dead-multi-word-key fix.

### Native-speaker review + example-corpus cleanup — BUG-171 through BUG-175

BUG-171 (above) reviewed ~40 dialects in four tiers; Khmer/Burmese/Lao/
Amharic and a fifth tier were flagged for real human review rather than
further automated passes. Checkpointing that work surfaced BUG-172: 66
pre-existing example-corpus failures (unqualified `Some`/`None`, dropped
`ref`, `Box(...)` vs `box(...)`, block-bodied `match` arms, a genuine
Georgian type-name-recognition compiler bug, several dialect-specific
one-offs), all closed. Three smaller, unrelated fixes rounded out this
window: the LSP's completion keyword lists had drifted 263 entries stale
from the lexer's real tables (BUG-173, now mechanically regenerated with a
CI guard against future re-drift); `break i;`/`continue i;` with `i` a
plain local variable was unconditionally misparsed as a label reference
(BUG-174); and the lexer treated any bare `'` as a label-start token even
mid-identifier, breaking Hebrew geresh notation like `פיבונאצ'י` (BUG-175
— fixing it exposed a second, previously-unreachable identifier-mangling
gap in both backends).

### Backend edge cases — BUG-177, BUG-178

A closure bound inside a block-expression `let` (rather than a top-level
`let`) failed to compile on the C backend (BUG-177). `abs()` on an integer
narrower than `i64` crashed the LLVM backend with a type-mismatched
`@llabs` call (BUG-178).

## Upgrade notes

- No breaking changes.
- `break inner` / `outer` / `middle` are new reserved positional targets
  inside a `break`/`continue` statement. A loop literally labeled `inner`,
  `outer`, or `middle` by coincidence still resolves to its real label —
  this only changes behavior for `break`/`continue` statements that
  previously failed to parse.
