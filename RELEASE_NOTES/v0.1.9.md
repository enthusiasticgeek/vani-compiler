# v0.1.9 — Named Loop Labels (2026-06-23)

## New language feature

### Named loop labels: `label: for/while` + `break label` + `continue label`

Any loop can now carry an explicit name. `break` and `continue` can target
any enclosing labeled loop by name — no positional keywords needed, no limit
on nesting depth:

```vani
outer: for i from 0 to 5 {
  middle: for j from 0 to 5 {
    inner: for k from 0 to 10 {
      if k == 2 { break inner; }     /* exits k-loop only              */
      if j == 3 { continue outer; }  /* skips to next i iteration      */
      if i == 4 { break middle; }    /* exits j+k loops; i continues   */
    }
  }
}
```

Syntax rules:
- Label a loop: `name: for ...` or `name: while ...` (plain identifier + colon)
- Exit a labeled loop: `break name;`
- Skip to next iteration of a labeled loop: `continue name;`
- Plain `break;` / `continue;` still target the innermost loop as before

Using an undefined label is a **compile error** with a clear diagnostic:
```
error: no enclosing loop is labeled 'nonexistent'
    break nonexistent;
```

Works for `for` and `while` loops. Both the SSA-C and LLVM backends emit
correct labeled exits (`goto __vani_break_NAME` / `goto __vani_continue_NAME`
in C; `br label %header` / `br label %exit` in LLVM IR).

## Replaces positional break

The v0.1.8 positional keywords `break inner` / `break middle` / `break outer`
(which targeted loops by position) are superseded by named labels. With named
labels the programmer is explicit about which loop they mean, the feature
scales to any nesting depth, and the intent is always clear at the `break`
site.

## Adversarial tests added

Three new edge-case programs:
- 3-deep nest with `break inner`, `break middle`, and `continue outer` (expected output: `24`)
- 2-loop `continue outer` skipping inner remainder and outer tail code (expected output: `8`)
- `xfail`: `break nonexistent` is rejected with a clean diagnostic (no panic)

All pass on both the C and LLVM backends.
